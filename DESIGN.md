## Identity

**"Dark Void + Liquid Lava"** dual-accent dark-only design system. Tailwind 4 CSS-first via `@theme`. Designed for *fast-scan terminal density*, not landing-page polish.

- **Dark Void** — luminance-stacked surface ramp from `#08090a` (canvas) to `#2a323a` (strong); never `#000`.
- **Liquid Lava** — orange brand accent `#ff6b35` (`oklch(0.705 0.193 39.2)`) used for momentum-hot tier, brand CTA, focus rings.
- **Functional Green** — `#22c55e` for active/selected/toggle-on states. Distinct semantic role from the brand orange.

User can swap the runtime accent hue among **5 palettes** (orange, blue, yellow, green, purple) via `data-theme` on `<html>` — see the pre-paint bootstrap in [src/app/layout.tsx#L208](./src/app/layout.tsx#L208). The OKLCH variants travel as `--color-*-oklch` aliases for chart engines that need a perceptual color space.

## Surfaces (6-level luminance ramp, no shadows)

Stack surfaces by **luminance, not shadow**. `--shadow-card: none` and `--shadow-card-hover: none` are **intentional and enforced** ([globals.css#L326-327](./src/app/globals.css#L326)). Use background-level stacking instead. Shadows are reserved for: focus rings (`--shadow-focus-*`), LIVE indicators (`--shadow-live*`), overlay elevation (`--shadow-overlay`, `--shadow-popover`), and brand-glow effects.

| Token | Hex | OKLCH | Use |
|---|---|---|---|
| `--color-bg-canvas` | `#08090a` | `oklch(0.139 0.003 246.3)` | Body background, deepest surface |
| `--color-bg-shell` | `#0b0d0f` | `oklch(0.158 0.005 248.2)` | Page shell, just above canvas |
| `--color-bg-raised` | `#101418` | `oklch(0.189 0.010 248.4)` | Cards (`--color-bg-card`) |
| `--color-bg-muted` | `#151a20` | `oklch(0.215 0.014 253.1)` | Card-hover, row-hover, secondary panels |
| `--color-bg-fill` | `#1d242b` | `oklch(0.257 0.017 248.5)` | Elevated controls, tertiary panels |
| `--color-bg-strong` | `#2a323a` | `oklch(0.313 0.018 248.4)` | Strongest accent surface |

Plus reference tokens: `--color-bg-graphite: #0c0c12`, `--color-bg-charcoal: #14141c` for special-case dark panels.

**Overlay:** `--color-bg-overlay: rgba(8, 9, 10, 0.82)` for modal/drawer scrim. **Never use bare `bg-black` — use `bg-bg-canvas` or the overlay token.** (This is the rule the SubredditHeatMapCanvas fix on `audit/imp-wave-1` enforces.)

## Borders (4 grades, hairline-first)

Hairlines structure the layout; thick borders are reserved.

| Token | Hex | Use |
|---|---|---|
| `--color-border-subtle` | `#1a2026` | Hairline dividers, faint outlines |
| `--color-border-default` | `#222a32` | Default card / control border |
| `--color-border-strong` | `#2f3942` | Active control, focused chip |
| `--color-border-hover` | `#4d5865` | Hover state on interactive borders |

Widths: `--border-width-hairline: 1px` (default), `--border-width-accent: 2px` (focused / selected), `--border-width-rail: 3px` (reserved for the *functional* left-rail accent — see `--shadow-row-hover` pattern below, **not** decorative left-tabs).

**On the `side-tab` anti-pattern that the impeccable CLI flags:** Trendingrepo uses `borderLeft: 3px solid <accent>` as a **functional color-key** that encodes per-repo / per-source identity (compare cards, news headers, OG share cards). Removing them destroys information. The impeccable CLI rule applies to decorative side-tabs; Trendingrepo's are not decorative. See [docs/audits/impeccable/PUNCH-LIST.md](./docs/audits/impeccable/PUNCH-LIST.md) "Recalibration" for the verdict.

## Radii — sharp, terminal-feel

**This is the biggest drift from the skill files.** Skill says "cards 12px"; reality:

```
--radius-button: 0.125rem  /* 2px */
--radius-card:   0.125rem  /* 2px */
--radius-card-lg:0.125rem  /* 2px */
--radius-xs: 2px
--radius-sm: 3px
--radius-md: 4px
--radius-lg: 6px
--radius-xl: 10px
--radius-2xl: 14px
--radius-pill: 99px      /* pill chips */
--radius-badge: 9999px   /* fully round */
```

**Terminal density. Sharp corners are intentional.** Don't round things to 12px — that reads as a marketing site, not a screener. The pixel/xs/sm/md/lg ladder covers all real card surfaces.

Tailwind utility mapping in practice: `rounded`, `rounded-md`, `rounded-lg` are heavily used. `rounded-xl` and `rounded-2xl` appear on hero / share-card surfaces only.

## Typography — three coexisting scales

**Three scales** are defined; pick the right one for the surface:

### `--text-*` — Tailwind-utility scale (default, body text)

```
2xs 10px, xs 11px, sm 12px, base 13px, md 14px, lg 16px,
xl 18px, 2xl 20px, 3xl 24px, 4xl 32px, 5xl 48px, 6xl 72px
```

Note `--text-base: 13px`, not 16px. Body copy is denser than typical web design.

### `--font-size-*` — terminal sub-scale (chips, dense rows, mono tickers)

```
2xs 7.5px, xs 8.5px, sm 9px, md 9.5px, lg 10px, xl 10.5px,
2xl 11px, 3xl 11.5px, 4xl 12px, 5xl 12.5px, 6xl 13px,
7xl 14px, 8xl 14.5px, 9xl 16.5px
```

Yes, 7.5px is a real token. Used on data-dense ticker rows.

### `--font-size-title-*` — hero / large surface scale

```
title-sm 18px, title-md 22px, title-lg 30px, title-xl 38px, title-2xl 48px
```

## Color semantics (not just hues — *roles*)

### Deltas / status

- `--color-positive` `#22c55e` — breakouts, "accelerating", up arrows
- `--color-negative` `#ff4d4d` — declines, errors
- `--color-warning` `#ffb547` — degraded sources, COLD freshness
- `--color-info` `#60a5fa` — informational chips
- `--color-functional` `#22c55e` — active/selected/toggle-ON (semantically distinct from `positive` even though hex matches; ties to `--shadow-row-hover` etc.)
- `--color-cyan` `#3ad6c5`, `--color-violet` `#a78bfa`, `--color-pink` `#f472b6`, `--color-gold` `#ffd24d`, `--color-silver` `#c0c5cc`, `--color-bronze` `#cd7f32` — chart series / tier-list decorations

### Heat tiers (momentum)

```
--color-heat-hot     = --color-accent          /* brand orange = hot */
--color-heat-warm    = --color-warning         /* amber */
--color-heat-neutral = #878787
--color-heat-cool    = --color-blue
```

### Chart series palette — **NOTE: drift**

Two definitions disagree:

- **globals.css** `--color-series-1..5`: `positive` → `blue` → `violet` → `warning` → `negative` (green→blue→purple→amber→red)
- **tokens.ts** `SERIES_PALETTE`: `accent` → `positive` → `cyan` → `warning` → `negative` (orange→green→cyan→amber→red)

Two different first-series colors (green vs orange). Either is internally consistent in its own consumer; cross-consumer drift will surface as "the chart accent doesn't match the page accent." **Open follow-up:** reconcile to one canonical order. ## Shadows — luminance-stacked, never card elevation

```
--shadow-card:           none        /* enforced */
--shadow-card-hover:     none        /* enforced */
--shadow-live:           0 0 0 3px rgba(34, 197, 94, 0.18)   /* LIVE pulse ring */
--shadow-live-small:     0 0 0 2px rgba(34, 197, 94, 0.18)
--shadow-live-soft:      0 0 0 6px rgba(34, 197, 94, 0.05)
--shadow-row-hover:      inset 3px 0 0 var(--color-functional)
                                                  /* row hover = green left-rail */
--shadow-overlay:        0 24px 48px rgba(0,0,0,0.55), 0 2px 6px rgba(0,0,0,0.35)
--shadow-popover:        0 12px 32px rgba(0,0,0,0.5),  0 2px 6px rgba(0,0,0,0.35)
--shadow-focus-danger:   0 0 0 3px rgba(255, 58, 92, 0.12)
```

**Pattern note**: `--shadow-row-hover: inset 3px 0 0 …` is a *functional* left-rail accent on row hover. The impeccable CLI may flag this as `side-tab` — it isn't. It's an interaction state, not decoration.

## Motion

```
--motion-duration-fast:        120ms
--motion-duration-base:        180ms
--motion-duration-pulse:       1.6s
--motion-duration-pulse-fast:  1.4s
--motion-duration-clock:       60s
--motion-ease-standard:        ease-in-out
--motion-ease-linear:          linear

--animate-fade-in:        fade-in 0.3s ease-out forwards
--animate-slide-up:       slide-up 0.35s cubic-bezier(0.2, 0.8, 0.2, 1) forwards
--animate-slide-in-left:  slide-in-left 0.28s  cubic-bezier(0.2, 0.8, 0.2, 1) forwards
--animate-slide-in-right: slide-in-right 0.28s cubic-bezier(0.2, 0.8, 0.2, 1) forwards
--animate-pulse-glow:     pulse-glow 2.2s ease-in-out infinite
```

Smooth, fast, **non-bouncy** easing (`cubic-bezier(0.2, 0.8, 0.2, 1)` = sharp deceleration). No springs, no overshoot. The impeccable rule "bounce / elastic easing feels dated" already holds in code.

## Chart theme — Echarts `trendingrepo-dark`

Defined in [src/lib/charts/theme/tokens.ts](./src/lib/charts/theme/tokens.ts), registered as `TR_DARK_THEME = "trendingrepo-dark"`. Reused via `<EChart theme="trendingrepo-dark">` in [src/components/charts/EChart.tsx](./src/components/charts/EChart.tsx).

Key spec:
- `color`: 7-slot series palette (orange→green→cyan→amber→red→violet→pink)
- `backgroundColor: transparent` (inherits surface from container)
- `textStyle.fontFamily: var(--font-mono, ui-monospace, …)` — mono everywhere
- `grid`: top 16 / right 18 / bottom 28 / left 48 — generous left margin for Y labels
- `categoryAxis` / `valueAxis` / `timeAxis`: line + tick hidden, only labels visible. Y-axis split lines dashed at 0.6 opacity.
- `legend`: `icon: "roundRect"`, subtle color
- `tooltip`: bg `--color-bg-canvas`, border `--color-border-default`, 1px width, mono font, no box-shadow, dashed axis pointer
- `dataZoom`: orange filler at 10% opacity, accent handle
- `line`: `smooth: false`, `symbol: "none"`, 2px stroke
- `bar`: top-rounded `[2,2,0,0]` corners
- `scatter`: 6px symbol, 85% opacity

Three other theme files exist but tokens.ts is the only one actively wired ([memory note](C:\Users\mirko\.claude\projects\c--dev-trendingrepo\memory) "Chart theme tokens heavily used while full/sparkline themes unused").

## Theming pre-paint

Inline `<script>` in `<head>` ([layout.tsx#L182-210](./src/app/layout.tsx#L182)) reads localStorage on first paint:
- `trendingrepo-v3-accent` — accent hue: `orange | blue | yellow | green | purple` (5 palettes, each with 5 stop values)
- `trendingrepo-v3-surface` — surface density: `sm | md | lg` (default `md`)
- Migrates legacy `starscreener-*` localStorage keys forward

Result attributes on `<html>`:
- `class="dark"` (always)
- `data-theme="orange"` (or chosen)
- `data-surface="md"`
- `data-v3-accent="orange"`

The pre-paint script writes runtime CSS vars `--color-accent`, `--color-brand`, `--v3-acc*`, `--v2-acc*` so any surface using brand-tied colors swaps with the chosen palette without flashing.
